## 2. 最终数据流

```text
用户终端
   │
   │ python -m app.main <command> ...
   ▼
argparse
   │
   ▼
main()
   │
   ├── JsonProjectStorage("data/projects.json")
   └── ProjectService(storage)
              │
              ▼
      create / list / get
      update / delete
              │
              ▼
      JsonProjectStorage
              │
      ┌───────┴────────┐
      │                │
    _load()          _write()
      │                │
      └───────┬────────┘
              ▼
      data/projects.json
```

职责边界：

```text
Model   → Project 数据结构
Service → 业务动作与业务规则
Storage → 数据存取与 JSON 持久化
main.py → CLI 参数解析、依赖组装、输出与最外层异常转换
```

异常链路：

```text
Storage 未找到
→ None / False
→ Service 转换
→ ProjectNotFoundError

重复项目名
→ Service
→ ProjectAlreadyExistsError

非法 JSON / 非法数据结构
→ JsonProjectStorage
→ ProjectStorageDataError

文件系统错误
→ OSError / 子类继续传播
→ CLI 边界转换为错误输出与退出码 1
```

## 3. 代码变更

### `app/exceptions.py`

新增：

```python
class ProjectAlreadyExistsError(Exception):
    ...

class ProjectStorageDataError(Exception):
    ...
```

继续保留 `ProjectNotFoundError`。当前没有为了三个异常建立复杂继承树。

### `app/storage.py`

`InMemoryProjectStorage` 在原有 `save / list_all / get_by_name` 基础上增加：

```text
update_by_name
delete_by_name
```

新增 `JsonProjectStorage`：

```text
_load()
_write()
save()
list_all()
get_by_name()
update_by_name()
delete_by_name()
```

关键行为：

- 文件不存在：返回 `[]`
- 空文件：返回 `[]`
- 非法 JSON：`ProjectStorageDataError`
- JSON 顶层不是 list：`ProjectStorageDataError`
- 条目不是 dict 或无法构造 `Project`：`ProjectStorageDataError`
- `_write()` 使用 `asdict()` 将 dataclass 转成可序列化数据
- 每次 CRUD 明确经过文件读取/写入边界

### `app/services.py`

当前共同 Storage 类型：

```python
ProjectStorage = InMemoryProjectStorage | JsonProjectStorage
```

这是 M1 阶段临时方案，不提前引入 Protocol / ABC / Repository。

`create_project()`：
- 检查重复名称
- 复制 `tags` / `members`
- 重复时抛 `ProjectAlreadyExistsError`

`update_project()`：
- 采用完整替换，不实现 PATCH
- 先确认当前 Project 存在
- 再检查新名称冲突
- 要求调用方显式传入 `name / description / tags / members`
- 已移除 `tags=[]` / `members=[]` 可变默认参数

`delete_project()`：
- Storage 返回 `False` 时由 Service 转换为 `ProjectNotFoundError`

## 8. 当前设计结论

1. `InMemoryProjectStorage` 与 `JsonProjectStorage` 保持不同、清晰的存储语义。
2. Service 不知道 JSON 文件具体怎么读写。
3. CLI 不直接操作 JSON。
4. Storage 表达存储事实，Service 解释业务意义。
5. 非法持久化数据不能伪装成“没有数据”。
6. Update 在 M1 阶段采用完整替换。
7. `ProjectStorage = InMemoryProjectStorage | JsonProjectStorage` 只是当前临时共同类型。
8. `data/projects.json` 当前是相对工作目录路径，应从项目根目录运行 CLI。
9. JSON 文件写入暂未实现并发锁、事务或原子替换；这些不属于 M1-T07。
10. CLI 是当前应用边界，负责把已知异常转换为用户可读输出与退出码。

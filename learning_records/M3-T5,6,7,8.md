## 一、核心数据流和职责

```text
HTTP Client
  → FastAPI Router（HTTP 参数校验、响应）
  → DbService（业务规则、跨表事务）
  → Repository（ORM 增删改查、筛选、JOIN）
  → SQLAlchemy Session / Engine
  → Psycopg → PostgreSQL
```

Repository 可以 `add()` / `flush()`，跨 Repository 的 `commit()` / `rollback()` 由 Service 事务边界统一管理。此次附件提供了行为测试，但没有提供 Router / Service / Repository 三份完整源码，因此不把完整源码静态审查写成已验证事实。

#### 独立完成的 `title_contains`

Repository 的核心做法：

```python
if title_contains is not None:
    escaped_title = (
        title_contains
        .replace("/", "//")
        .replace("%", "/%")
        .replace("_", "/_")
    )

    filters.append(
        TaskRow.title.ilike(
            f"%{escaped_title}%",
            escape="/",
        )
    )
```

评价：这是正确的带 ESCAPE 的 `ILIKE` 包含匹配写法。将作为转义字符的 `/` 本身先双写，再将 `%`、`_` 转为字面字符，可以避免输入被意外解释为 LIKE 通配符。该行为不需要额外 Schema migration。

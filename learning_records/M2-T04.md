## 2. 已实现的 Request Schema 与学习路由

本任务使用 Pydantic `BaseModel` 定义 HTTP Request Schema：

```python
class ProjectRequestBody(BaseModel):
    name: str = Field(min_length=1)
    description: str | None = None
    tags: list[str] = Field(default_factory=list)
    members: list[str] = Field(default_factory=list)
```

学习路由：

```text
POST /request-body-demo
```

它只执行：

```text
接收 JSON Body
→ Pydantic 解析与校验
→ 构造 ProjectRequestBody Python object
→ endpoint
→ model_dump()

```

当前已有的 `Project` dataclass 继续作为领域数据对象，不因为学习 Pydantic 而被替换。

## 3. Request Schema 核心结论

### Required 与 Optional

```python
name: str
```

没有默认值，因此字段必须出现在 Request Body 中。

```python
description: str | None = None
```

既允许值为 `None`，也允许客户端省略该字段。

需要继续区分：

```text
允许 None
≠
允许字段缺失
```

例如：

```python
description: str | None
```

虽然值类型允许 `None`，但没有默认值时字段仍然是 required。

### `Field(min_length=1)`

```python
name: str = Field(min_length=1)
```

不仅要求 `name` 是字符串，还要求字符串长度至少为 1。

因此：

```json
{"name": ""}
```

虽然类型仍然是 `str`，但字段约束不满足，仍会得到 422。

### `default_factory=list`

```python
tags: list[str] = Field(default_factory=list)
members: list[str] = Field(default_factory=list)
```

继续保持显式 factory，避免把可变对象作为共享默认值，并与 M1 已建立的可变对象纪律保持一致。

## 5. 实际 HTTP 验证

### A. 合法 Request Body

请求：

```json
{
  "name": "alpha",
  "description": "Pydantic demo",
  "tags": ["python", "fastapi"],
  "members": ["ivian"]
}
```

实际状态：

```text
HTTP/1.1 200 OK
content-length: 94
content-type: application/json
```

结果：✅ 路由匹配、Body 解析和 Pydantic 校验成功。

### B. 缺少 required 字段 `name`

请求：

```json
{
  "tags": ["python"]
}
```

实际状态：

```text
HTTP/1.1 422 Unprocessable Content
```

响应中仍可确认：

```text
type: missing
loc: body / name
```

结果：✅ 缺少 required 字段时，在 endpoint 正常执行前被拒绝。

### C. `tags` 类型错误

请求：

```json
{
  "name": "alpha",
  "tags": "python"
}
```

实际状态：

```text
HTTP/1.1 422 Unprocessable Content
```

响应中仍可确认：

```text
type: list_type
loc: body / tags
```

结果：✅ `tags` 必须符合 `list[str]` 的 Request Schema。

### D. `name` 字段约束失败

请求：

```json
{
  "name": ""
}
```

实际响应完整可见：

```text
HTTP/1.1 422 Unprocessable Content

type: string_too_short
loc: body / name
msg: String should have at least 1 character
ctx.min_length: 1
```

结果：✅ 类型正确但字段约束失败时，同样返回 422。

```text
   └─ 校验失败 → RequestValidationError
                → FastAPI 默认异常处理
                → 422
                → endpoint 不正常执行
```

结果：✅ 通过

### B. 为什么错误 Body 不会正常进入 endpoint

已能独立说明：

```text
FastAPI 不会把客户端原始 JSON 直接交给 endpoint。

请求先经过路由匹配、Body 读取、JSON 解析，
再按照 endpoint 参数声明使用 ProjectRequestBody 做解析、转换和校验。

只有校验成功，FastAPI 才会构造 ProjectRequestBody Python object，
并把这个对象传入 endpoint。

如果校验失败，请求在 HTTP 边界就进入 RequestValidationError / 422 流程，
endpoint 不会按正常路径执行。
```

结果：✅ 通过

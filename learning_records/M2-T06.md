## 3. 统一异常处理机制

M2-T06 在 FastAPI application 上注册统一 exception handler：

```python
@app.exception_handler(ProjectNotFoundError)
async def project_not_found_exception_handler(
    _request: Request,
    exc: ProjectNotFoundError,
) -> JSONResponse:
    return JSONResponse(
        status_code=status.HTTP_404_NOT_FOUND,
        content={
            "detail": str(exc),
        },
    )
```

以及：

```python
@app.exception_handler(ProjectAlreadyExistsError)
async def project_already_exists_exception_handler(
    _request: Request,
    exc: ProjectAlreadyExistsError,
) -> JSONResponse:
    return JSONResponse(
        status_code=status.HTTP_409_CONFLICT,
        content={
            "detail": str(exc),
        },
    )
```

因此同一种业务异常不需要在多个 endpoint 中重复转换。

## 4. 为什么不用 endpoint 内重复 try/except

不采用：

```text
GET route
→ try / except ProjectNotFoundError

PATCH route
→ try / except ProjectNotFoundError

DELETE route
→ try / except ProjectNotFoundError

POST route
→ try / except ProjectAlreadyExistsError
```

因为实际规则只有：

```text
ProjectNotFoundError
→ 404

ProjectAlreadyExistsError
→ 409
```

将转换集中到 FastAPI application 的 exception handler 后，可以保证：

```text
同一个异常
→ 同一种 HTTP 表达
```

也避免 endpoint 被重复异常翻译代码淹没。

## 5. 为什么 Service 不抛 HTTPException

本卡无 AI 验收已经能正确说明：

```text
ProjectService 是业务层
→ 不应依赖 HTTP / FastAPI

同一 ProjectService
→ 同时服务 CLI 和 Web
```

因此 Service 应继续抛：

```text
ProjectNotFoundError
ProjectAlreadyExistsError
```

不同入口再分别翻译：

```text
CLI
→ Error 文本
→ exit code 1

Web
→ HTTP 404 / 409 JSON Response
```

如果 Service 直接抛：

```text
HTTPException(404)
```

则业务层会反向依赖 HTTP 框架，CLI 也会被迫理解 HTTP 语义，破坏当前分层。

## 6. 404 / 409 / 422 / 500 的边界

### 404 Not Found

表示请求所指向的业务资源不存在：

```text
GET /projects/missing
DELETE /projects/missing
PATCH /projects/missing
```

链路：

```text
Route
→ Service
→ ProjectNotFoundError
→ FastAPI exception handler
→ 404
```

### 409 Conflict

表示请求本身结构合法，但与服务器当前业务状态冲突：

```text
POST 创建重复 project
PATCH 把 project 改成已存在名称
```

链路：

```text
Pydantic 校验成功
→ Route
→ Service
→ ProjectAlreadyExistsError
→ FastAPI exception handler
→ 409
```

### 422 Unprocessable Content

表示 HTTP 输入没有通过 FastAPI / Pydantic 校验：

```text
name = ""
```

链路：

```text
Request
→ FastAPI / Pydantic
→ RequestValidationError
→ FastAPI 默认 handler
→ 422
```

这类请求不会按正常业务路径进入 Service。

### 500 Internal Server Error

代表未被应用正常处理的服务器内部错误，例如：

```python
1 / 0
```

它既不是“不存在”，也不是“业务冲突”。

因此不能使用：

```python
except Exception:
    return 404 / 409
```

来伪装未知错误。

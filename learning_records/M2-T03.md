## 3. Path Parameter 与 Query Parameter

### Path Parameter

路由：

```text
/parameter-demo/{project_name}
```

请求：

```text
/parameter-demo/alpha
```

其中：

```text
alpha
→ 匹配 {project_name}
→ project_name = "alpha"
```

FastAPI 根据 route path 中的：

```text
{project_name}
```

判断它来自 Path。

参数类型：

```python
project_name: str
```

则表示 FastAPI 最终需要为 endpoint 提供 Python `str`。

Path Parameter 属于 URL 路径结构本身，因此在 FastAPI 中始终 required。

例如：

```text
/parameter-demo/alpha
```

和：

```text
/parameter-demo/
```

并不是同一条完整路径。

---

### Query Parameter

例如：

```text
?limit=5&include_archived=true&offset=10
```

其中：

```text
limit=5
include_archived=true
offset=10
```

均属于 Query String。

它们没有出现在：

```text
/parameter-demo/{project_name}
```

的路径模板中，因此 FastAPI 将对应函数参数识别为 Query Parameters。

当前：

```text
limit
include_archived
offset
```

均声明了默认值，因此客户端可以省略。

需要注意：

```text
Query Parameter ≠ 天然 optional
```

更准确的结论是：

```text
Query Parameter
→ 可以 required
→ 也可以通过默认值变成 optional

Path Parameter
→ 属于路径模板
→ 始终 required
```

## 4. HTTP 数据与 Python 类型

HTTP URL 中的数据不是 Python 对象。

例如：

```text
?limit=8
```

网络请求中携带的是文本形式的数据。

FastAPI 在调用 endpoint 之前读取函数签名中的类型信息，例如：

```python
limit: int
```

并完成参数解析与校验。

可以建立如下心智模型：

```text
HTTP Query String
limit=8
   │
   ▼
文本形式 "8"
   │
   ▼
FastAPI 参数处理
   │
   ├── 查看参数来源
   │
   └── 查看 Python 类型注解 int
   ▼
解析 / 校验
   │
   ▼
Python int 8
   │
   ▼
endpoint(limit=8)
```

同理：

```text
include_archived=true
```

最终能够进入函数成为：

```python
True
```

而不是字符串：

```python
"true"
```

因此 FastAPI 中的 Python 类型注解不仅用于代码阅读和 IDE，也参与请求参数处理。

## 5. 参数校验发生在 endpoint 之前

实际执行：

```text
GET /parameter-demo/alpha?limit=abc
```

其中：

```text
limit
```

要求成为：

```python
int
```

但输入：

```text
"abc"
```

无法被解析成合法整数。

真实执行边界是：

```text
Client
→ Uvicorn
→ FastAPI
→ 路由匹配
→ 参数提取
→ 参数解析 / 校验
→ 失败
→ HTTP 422
```

而不是：

```text
Client
→ endpoint
→ endpoint 内部手动 int("abc")
→ Python 异常
```

因此此次请求不会正常执行 `read_parameter_demo()`。

本次环境中的实际状态行为：

```text
HTTP 422 Unprocessable Content
```

响应中指出错误位置为：

```text
query → limit
```

错误类型为：

```text
int_parsing
```

这说明失败发生在 Query Parameter `limit` 的整数解析阶段。

本任务只要求建立这一边界认知。

422、Request Body 和 Pydantic 请求模型将在 M2-T04 正式继续学习。

## 12. 本任务形成的核心结论

M2-T03 完成后，应稳定掌握：

```text
Path / Query 是参数来源
Python 类型注解决定目标类型
```

不能混淆成：

```text
str 决定 Path
int 决定 Query
```

正确判断顺序是：

```text
参数名字是否出现在 route path 中？
│
├── 是
│   → Path Parameter
│
└── 否
    → 当前简单声明下作为 Query Parameter

然后再看类型注解：
str / int / bool / ...
→ 决定 FastAPI 要解析成什么 Python 类型
```

同时建立以下请求边界：

```text
参数成功解析
→ endpoint 得到已经处理后的 Python 值

参数解析失败
→ endpoint 不正常执行
→ FastAPI 在边界层返回参数错误响应
```

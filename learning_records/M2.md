```text

→ Response
```

```text

+

```

```text

```

## 9. PATCH 部分更新

现有 Service update 保持完整替换语义。

HTTP PATCH Route 使用：

```python
body.model_dump(exclude_unset=True)
```

识别客户端真正发送的字段，再与当前 Project 合并，最后调用 Service。

因此：

```text
HTTP partial update
```

被 Router 翻译成：

```text
Service full replacement update
```

并建立：

```text
字段没传
≠
字段显式为 null
```

的语义差异。

## 10. 业务异常 → HTTP

Service 继续使用业务异常：

```text
ProjectNotFoundError
ProjectAlreadyExistsError
```

FastAPI application 在 HTTP 边界统一转换：

```text
ProjectNotFoundError
→ 404 Not Found

ProjectAlreadyExistsError
→ 409 Conflict
```

没有：

```text
让 Service 抛 HTTPException
```

因此同一个 Service 仍可被：

```text
CLI
Web
```

共同复用。

## 11. 422 / 404 / 409 / 500 边界

M2 已建立清晰的失败层级：

```text
422
→ Request / Pydantic 校验失败

404
→ 资源不存在
或 Route 根本不存在，需要结合日志继续区分

409
→ 请求结构合法，但与当前业务状态冲突

500
→ 未处理服务器内部错误
```

未知异常不会被：

```text
except Exception
→ return 404 / 409
```

错误吞掉。

## 18. M2 关键设计结论

- HTTP 与 REST 不等价。
- Uvicorn 是 Server；FastAPI 是 Framework。
- Router 负责 HTTP 协议翻译；Service 负责业务规则。
- Web 与 CLI 复用同一个 Service。
- API Request / Response Schema 不等同于 Domain dataclass。
- Pydantic 在 endpoint 正常业务逻辑前完成输入校验。
- 业务异常保持业务语义，在 Web 边界转换为 HTTP。
- Service 不依赖 FastAPI / `HTTPException`。
- PATCH 部分更新语义由 Router 转换为 Service 当前完整替换语义。
- 日志和异常处理是不同职责。
- 未知异常可以记录后重新抛出，但不能被错误吞成 4xx。
- HTTP Status 相同不代表故障发生在同一层。
- TestClient 测的是 ASGI application，不需要真实 TCP/Uvicorn。
- Web API 测试必须隔离数据状态，不修改真实开发数据。
- 只断言 status code 不足以证明业务行为正确。
- 不同测试层共同缩小故障定位范围。
